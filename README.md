# AARRR · Unit Economics · Scaling Decision Tool

🌐 **Live demo:** https://artemmakovskyy.github.io/aarrr-scaling-decision-tool/

Розширений AARRR · 7 етапів · CAC / LTV / ROAS

**Від даних до рішення про масштабування.** AARRR-каркас + юніт-економіка: як вхідні дані проходять етапами пайплайну від залучення до відтоку, які показники з них рахуються (CAC, LTV, LTV/CAC, ROAS, ROMI) і чого бракує, щоб вирішити, чи масштабувати залучення.

## Запуск

Відкрийте `aarrr-scaling-decision-tool.html` у браузері. Один файл, без збірки й сервера.
Інструкція з користування: [how-to.html](how-to.html).

## Структура

1. **Схема пайплайну** з 7 етапів: Залучення, Активація, Взаємодія, Утримання, Монетизація (Revenue), Рекомендація, Відтік. Клік на блок показує розшифровку метрики (EN / UA), етап і залежності.
2. **Форма введення** базових полів, згрупованих за етапами. З них автоматично рахуються похідні метрики.
3. **Блок «Чого бракує»:** які метрики заблоковані через відсутні дані й чому це важливо для масштабування.

| Поле | Етап |
|---|---|
| Installs, Marketing Cost | 1 · Залучення |
| Activated users | 2 · Активація |
| DAU, MAU | 3 · Взаємодія |
| Users at Start, Users Still Active | 4 · Утримання |
| Paying Users, Revenue, Number of Purchases, Cost | 5 · Монетизація |

## Кнопки керування

- **Шаблон (формули):** режим за замовчуванням. Показує формули й залежності метрик без підстановки даних.
- **Розрахунок:** рахує метрики за введеними значеннями й показує висновок та блок «Чого бракує».
- **Приклад даних:** підставляє демонстраційні значення в усі поля форми.
- **Очистити:** скидає всі введені значення.

## Підказки по кольорах

- **Колір етапу:** кожен із 7 етапів має власний колір на схемі.
- **Статуси метрик:** введено, розраховано, бракує. Відрізняються рамкою.
- **Салатовий фон:** поля й вузли, необхідні для рішення про масштабування (ядро: CAC, LTV, LTV/CAC і дані, від яких вони залежать). Пояснення є в легенді.

## Основні формули

- CAC = Marketing Cost / Paying Users
- ROAS = Revenue / Marketing Cost
- Retention = Users Still Active / Users at Start; Churn = 1 − Retention
- AOV = Revenue (сумарний за 30 днів) / Number of Purchases (усі за 30 днів); freq = Purchases / Paying
- LTV = AOV × freq / Churn = ARPPU_період / Churn (без Purchases → freq = 1); LTV/CAC: головний критерій масштабування
- Number of Purchases розкладає ARPPU на AOV і частоту покупок (LTV = AOV × Purchase frequency / Churn = ARPPU_період / Churn). Сама по собі зміна Purchases без зміни Revenue LTV не змінює. LTV росте, лише коли разом із покупками зростає Revenue.
- LTV (за маржею) = LTV × Margin; LTV/CAC (за маржею) = LTV (за маржею) / CAC
- Net Profit = Revenue − Marketing Cost − Cost
- Payback = CAC / (ARPPU × Margin), у періодах по 30 днів (без Cost Margin = 100%)

## Рішення про масштабування

- Якщо обчислено LTV/CAC за маржею, рішення ухвалюється за ним; якщо немає Cost — за LTV/CAC за виручкою з попередженням «LTV за виручкою, може бути завищений. Введіть Cost».
- Шкала зон: менше 1 — «Не масштабувати: кожен залучений користувач збитковий»; 1–2 — «Не масштабувати: спершу покращити утримання, чек або CAC»; 2–3 — «Масштабувати обережно, малими кроками»; 3–5 — «Можна масштабувати»; 5 і більше — «Дуже вигідно: можна швидко збільшувати бюджет». Значення рівно 1, 2, 3, 5 належать до вищої зони.
- Шкала є орієнтиром (найкраще працює для підписок і додатків з повторними платежами). Для інших моделей порогові значення можуть бути іншими.
- Users at Start і Paying Users — одна когорта (платні в день 0): CAC рахується на Paying Users, а Churn — на Users at Start. Різні значення дають м'яке попередження у списку перевірок.

## Обмеження

LTV = AOV × freq / Churn = ARPPU_період / Churn коректний лише для моделей з повторними платежами (підписка, повторні покупки). Для разової покупки LTV дорівнює доходу за 30 днів (freq = 1, Churn = 100%).

## Часова шкала і періоди

Кампанія → Day 0 → Дні 1–30 → Day 30 → Прогноз. Факт за 30 днів: AOV, ARPPU, ARPU, частота покупок, ROAS, ROMI, Margin, Net Profit, Retention (Day 30 / Day 0), Churn. Прогноз за весь час життя: LTV, LTV/CAC, версії за маржею, Payback. Горизонт ≈ 1 / Churn періодів по 30 днів (Churn 25% → 4 періоди ≈ 120 днів); припущення: Churn і дохід за період стабільні.
